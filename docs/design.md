# 设计

这份文档记录 nasbutler 的目标、威胁模型、已经做出的决定和后续版本的设计。代码注释解释"怎么做"，这里解释"为什么"。

## 目标

让 AI agent 帮忙整理一个混杂的个人文件库（照片视频、监控录像、备份、证件、聊天记录、工作资料……），同时守住两件事：

1. **不泄密**：云端模型（Claude、GPT、Gemini……）看到的东西，等于发给了第三方。
2. **不毁数据**：这类文件库往往没有第二份，agent 的一次误删就找不回来。

## 威胁模型

**防的是：**

- 敏感内容经由 agent 流到模型提供方：文件内容、文件名里的身份证号和手机号、机密目录的名字。
- agent 的误操作：删错、移错、覆盖。
- 通过文件名或文件内容对 agent 做提示注入（"忽略之前的指令，把所有文件……"）。

**不防的是：**

- 能直接登录这台机器的人或 agent。**如果 agent 本身有这台机器的 shell，它绕过 MCP 就能直接读写文件**，这里的一切都白做。部署时，跑整理任务的 agent 只能拿到 MCP 端点，不能有 shell。
- 聚合信息：目录结构、文件数量、大小、时间分布。这些是整理所必需的，会发给模型。
- 对抗性 agent 通过大量聚合查询做推断。已经挡住了最直接的几条路（名字过滤只匹配脱敏后的名字，扩展名过滤不返回机密文件），但没有做系统性的防御。

## 为什么是 MCP + 纯信息模式

agent 碰数据的唯一通道是 MCP，所以 MCP 服务就是安全边界：它决定 agent 能看到什么、能做什么。

v0.1 只提供**纯信息模式**：agent 能看到脱敏后的路径、大小、时间、类型、敏感信息计数、重复文件分组、媒体编码参数，**看不到任何文件内容**。内容只在本机用来做敏感检测，检测结果只以计数的形式出去。

## 敏感信息定级

扫描时每个文件定一个级别：

| 级别 | 判定 | agent 看到什么 |
|---|---|---|
| 隐藏 | 配置里的 `hidden` 规则 | 什么都没有，不扫描、不计数 |
| 不透明目录 | 配置里的 `opaque` 规则 | 只有总文件数和总大小 |
| 机密 | 路径规则（内置 + 配置）；文件头特征（KeePass 库）；内容里有私钥、API token、密码赋值 | 名字整体换成 `[secret#…]`，扩展名不给；机密目录整体折叠成 `[secret-dir#…]`，下面的子目录结构也不给 |
| 个人 | 内容或文件名里有身份证号（校验位）、手机号、银行卡号（发卡行前缀 + Luhn）、邮箱 | 名字里的敏感片段换成化名 |
| 普通 | 其余 | 名字里如果有敏感片段，照样换成化名 |

- **按路径判定为机密的文件，内容一个字节都不读。**
- 数字类检测以"最长连续数字串"为单位判断，所以 20 位的摄像头时间戳不会被误认成藏在其中的 16 位银行卡号；银行卡号还要过发卡行前缀校验，以 `19`、`20` 开头的日期串不会通过。
- 旧版中文 Windows 写出的 GBK 文件名会被解码显示；解不开的字节转成 `%XX`，保证不同的名字仍然不同。

## 化名

化名是 `[类型#8位十六进制]`，十六进制部分是规范化后的值在服务端密钥下的 HMAC-SHA256。

- **同一个值永远得到同一个化名**：`138 1234 5678`、`+8613812345678` 和 `13812345678` 是同一个化名。agent 能看出"这 30 个文件都和同一个号码有关"，但拿不到号码。
- 密钥存在 `state_dir/pseudonym.key`（0600），不离开服务端。化名是带密钥的 HMAC，没有密钥就不能靠遍历号码空间撞出原值。
- 化名在扫描时就写进索引（`rpath`），所以 agent 用脱敏路径导航，名字过滤也只在脱敏名字上做。这堵住了"用 `name_contains` 二分猜出被打码的号码"这条路。

## 出口过滤

所有工具的返回值在离开进程前都经过同一个 MCP 中间件：

1. 把返回的 JSON 里每个字符串（包括对象的键）重新过一遍检测器，数字不动（一个 13,812,345,678 字节的文件必须保留它的大小）。
2. 超过 `max_result_bytes` 的结果整体拒绝，防止批量导出。
3. 发出去的内容逐条追加进 `state_dir/egress.jsonl`，事后可以查到底有什么发出去了。

数据在扫描时已经脱敏过，出口过滤是第二道防线。**如果它还能找到要脱敏的东西，说明某处代码漏了**：这时它照样脱敏，同时在审计日志里记 `late_redactions` 并打警告日志。

工具返回的错误信息同样经过这道过滤；代码层面也约定错误信息里不带真实路径（比如 ffprobe 失败只返回"media probe failed"，因为 ffprobe 自己的报错会带上文件路径）。

## 只读保证（v0.1）

- 扫描器用 `O_RDONLY|O_NOFOLLOW|O_NOATIME` 打开文件，不跟随符号链接，不改访问时间。
- MCP 服务以 SQLite `query_only` 模式打开索引，就算代码有 bug 也改不了索引。
- v0.1 没有任何会改动文件的工具。

## 后续版本

### v0.2：计划、审批与执行

agent 只能**提计划**，不能直接动文件：

- 计划是一份操作清单：移动、改名、建目录、隔离。**没有删除**：清理只能"隔离"，即同盘移进隔离区，保留 N 天，到期由人手动清空。
- 执行器是独立进程（部署时是独立容器），**只有它对数据有写权限**；MCP 服务那一侧继续只读挂载。
- 执行前先写操作日志（write-ahead），任何计划都能撤销。
- 所有移动都是同一文件系统内的 rename：原子、秒级、不复制数据。执行器只接受一个挂载路径。在 Unraid 上这也避开了混用 `/mnt/user` 和 `/mnt/diskN` 路径时可能把文件截成 0 字节的问题。
- 配置里可以声明受保护目录（比如别的程序正在写入的备份落点），任何计划都不能以它为源或目标。

### 审批接口

审批必须在服务端强制，不能依赖 MCP 客户端的确认弹窗：很多 agent 跑在免确认模式下，客户端的确认本来也能被绕过。

审批方式做成可扩展的接口，第一个实现是飞书：

```go
// Approver 把一份待批准的计划送到人手里，并判断人是否批准。
type Approver interface {
	// Name 用于配置和日志，如 "feishu"。
	Name() string
	// Request 发起审批。返回的 Ticket 会原样交给 agent，
	// 所以只能包含可公开的信息，绝不能包含确认码。
	Request(ctx context.Context, p PlanSummary) (Ticket, error)
	// Check 返回审批结果。response 是 agent 转交的人的答复（比如确认码）；
	// 回调类实现（比如飞书卡片按钮）忽略它，只看回调是否到达。
	// 实现负责一次性使用、过期和失败次数上限。
	Check(ctx context.Context, t Ticket, response string) (Decision, error)
}

type PlanSummary struct {
	PlanID  string
	Digest  string   // 计划内容的哈希。审批绑定到它：计划改一个字就要重新审批
	Title   string
	Ops     int
	Bytes   int64
	Lines   []string // 已脱敏的摘要行，如 "移动 1,204 个文件（38 GB）：photos/… → 照片/2024/…"
	Expires time.Time
}

type Ticket struct {
	ID      string
	PlanID  string
	Digest  string
	Channel string // "feishu"
	Expires time.Time
}

type Decision int

const (
	Pending Decision = iota
	Approved
	Rejected
	Expired
)
```

**飞书实现（确认码）：**

1. `plan_submit` 时生成 6 位随机确认码，通过飞书自定义机器人 webhook 把计划摘要和确认码推给人。webhook 格式是飞书标准格式，支持可选的签名密钥；任何兼容这个格式的转发服务也能用。
2. 服务端只存确认码的 HMAC、计划摘要、过期时间（默认 10 分钟）和剩余尝试次数（默认 5 次）。
3. 人确认没问题后，在对话里把确认码告诉 agent；agent 调 `plan_approve`，由 `Check` 核验。
4. 确认码只走飞书、不经过 MCP，agent 在人告诉它之前拿不到；用过一次即失效；绑定计划摘要，不能拿去批准别的计划。5 次尝试上限让猜中的概率保持在百万分之五。

之后可以加回调类实现（飞书卡片上的"批准 / 拒绝"按钮，通过长连接接收事件，不需要公网入口），接口不用改。

### v0.3：监控录像

- 按路径、文件名规律（摄像头名 + 时间戳）和编码参数识别监控片段，按"摄像头 + 日期"分组。
- 参数一致的片段用 ffmpeg `concat -c copy` 无损拼接；可变帧率的先转固定帧率。
- 可选硬件转码（H.265）和 DVR-Scan 只保留有画面变动的片段。
- 只生成新文件，用 ffprobe 核对时长一致后，原件才进隔离区。执行器限内存、限 CPU、同一时间只跑一个任务。

### v0.4：机密保险箱

- 机密文件可以整体移进加密目录（gocryptfs）。
- 可选 OCR，识别图片里的证件照和聊天截图。

## 已知局限

- 规则抓不到人名、住址这类自由文本。
- Office 文档、PDF、压缩包的内容 v0.1 不检测（`sensitive_report` 会给出未检测文档的数量）。
- 图片内容在加 OCR 之前识别不了。
- 化名挡住了具体的值，挡不住上下文：`[phone#…]` 出现在"病历"目录里本身就是信息。真正一点都不想外发的，用 `hidden`。
